# help.stemcounts

StemCounts help / docs site. Static site built with
[Astro Starlight](https://starlight.astro.build/) — markdown + MDX
content, zero JS shipped to the user by default, deployed to
`help.stemcounts.com`.

This is **separate from the main StemCounts app** in
[`tomscott1/builder-sc-frontend`](https://github.com/tomscott1/builder-sc-frontend).
It does not call StemCounts APIs and does not require auth. Treat it as
the canonical home for end-user guides, walkthroughs, and release notes.

The architecture mirrors
[`mira-advisory/planease-help`](https://github.com/mira-advisory/planease-help)
deliberately — anyone who has worked on that repo will navigate this one
without surprises.

## Brand tokens

**Everything brand-related lives in `src/styles/custom.css`.** That file is
the single source of truth for the docs site. Comment block at the top
maps each token back to its canonical source in
`tomscott1/builder-sc-frontend`. If you change a brand colour, change
it in both places in the same commit.

Quick reference:

| Token | Value | Use |
|---|---|---|
| `--sl-color-accent` | `#1B4332` (forest green) | Logo accent, inline links, hover borders |
| `--cta-primary` | `#FF6F61` (coral) | Primary CTAs, active sidebar item, hero button |
| Secondary teal | `#2A9D8F` | Logo accent (favicon + brand mark) |
| `--sl-font` | Inter | Body + headings |
| `--sl-radius` | `8px` | Cards, buttons, asides |

Logo source: `src/assets/stemcounts-logo.svg` (copy of `coral-teal.svg`
from the main app's `public/logos/` directory).

No inline hex literals in components or articles — always reference the
CSS vars or the `--cta-*` tokens.

## Writing an article

1. Pick the right section folder under `src/content/docs/` (or create one).
2. Add a new `.mdx` file. The file name becomes the URL slug.
3. Frontmatter at the top:

   ```mdx
   ---
   title: My new article
   description: One-line summary used for OG tags + sidebar tooltip.
   sidebar:
     order: 2          # optional — controls position within the section
   ---
   ```

4. Use Starlight's [built-in components](https://starlight.astro.build/components/) —
   `<Steps>`, `<Aside>`, `<Card>`, `<Tabs>`, `<Badge>` etc. Imported per page:

   ```mdx
   import { Steps, Aside } from "@astrojs/starlight/components";
   ```

5. For screenshots and video, use the project's `<HelpMedia>` component.
   It resolves a stable slug against the help-media manifest:

   ```mdx
   import HelpMedia from "../../components/HelpMedia.astro";

   <HelpMedia id="catalog-browse" />
   ```

   See [`src/components/HelpMedia.astro`](src/components/HelpMedia.astro)
   for the full prop list (alt, caption, width, figure).

## Help-media pipeline

The `<HelpMedia>` component reads a flat `manifest.json` listing every
screenshot and video by slug. The default URL is set in
[`src/lib/manifest.ts`](src/lib/manifest.ts) and can be overridden per
build via `PUBLIC_HELP_MEDIA_MANIFEST_URL`.

**Current status:** The StemCounts help-media pipeline (CDN bucket +
manifest-writer) does not exist yet. The default URL is a placeholder.
Until it's wired up, `<HelpMedia>` renders a clearly visible
"Missing media" warning instead of failing the build.

## Deploy

Deployment target: **AWS Amplify** at `help.stemcounts.com`.

- Branch: `main` → production
- Build spec: [`amplify.yml`](./amplify.yml). `npm ci` + `npm run build`,
  artifacts in `dist/`. No SSR, no Lambda — pure static + CDN.
- Cache headers: [`customHttp.yml`](./customHttp.yml). HTML revalidates
  every 5 min so post-deploy CloudFront edges turn over quickly.

The Amplify app does **not** exist yet. To create it:

1. Sign in to AWS Amplify console (region of your choice — `ap-southeast-2`
   matches planease-help).
2. **New app → Host web app → GitHub** → pick
   `mira-advisory/help.stemcounts`, branch `main`.
3. Amplify auto-detects `amplify.yml`. Confirm and deploy.
4. Once the first build is green, **Domain management → Add domain** →
   `stemcounts.com`, subdomain `help` → produces `help.stemcounts.com`.
5. (Optional) Add the `staging` branch for previews at a separate
   subdomain.

Until that's done, the site is preview-only via `npm run dev` /
`npm run preview` locally.

## SEO

- `@astrojs/sitemap` integration writes `/sitemap-index.xml` at build time.
- [`public/robots.txt`](public/robots.txt) points crawlers at the sitemap.
- `site` in `astro.config.mjs` controls canonical URLs and OG tags —
  must match the live host exactly.
